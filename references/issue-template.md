# 问题记录模板

新条目使用以下格式。按项目当前编号顺延，日期用 YYYY-MM-DD。可选字段按已有证据填写，待确认事项留在对应段落。

```markdown
## ISSUE-001 问题标题

| 属性 | 内容 |
|---|---|
| 状态 | 待排查 |
| 类型 | 例如数据兼容、环境配置或发布 |
| 首次发现 | YYYY-MM-DD |
| 最近更新 | YYYY-MM-DD |
| 影响范围 | 受影响的环境、功能或用户 |
| 关联位置 | 项目相对路径、方法、接口或配置项 |

### 一、什么问题、什么表现

用户进行了什么操作，遇到什么异常，影响了哪些场景。

### 二、复现与现象

记录必要的环境、版本、前置条件和复现步骤。写出预期结果、实际结果和经脱敏的关键证据。

### 三、排查思路是什么

写明各项检查的发现、排除的原因，以及证据支持的根因。尚未验证的判断标为待确认。

### 四、怎么解决的

记录实际执行的操作和观察到的结果。写清是临时恢复还是根因修复，必要时记录回退方式。尚未处理时记录当前进度。

### 五、后续修复与验收

列出已验证和待验证的场景，注明实测、源码检查或用户确认。按需关联后续待办和相关问题编号。
```

状态可用待排查、排查中、已定位、暂时恢复、待验收、已解决、再次出现、暂缓处理。根据实际进展直接使用合适的状态。
